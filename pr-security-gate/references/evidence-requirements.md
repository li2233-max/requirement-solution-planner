# 可验证证据要求

## 证据规则

只接受审查者可复现或可直接检查的证据：带结果的测试名/命令、扫描报告、关键 HTTP 请求/响应、diff 中可见的服务端控制和已核验的风险接受记录。没有材料时写“未提供”，不要猜测或把计划执行当作通过。

没有实际 PR diff 时，不能将摘要、作者说明或模型结论视作 diff 证据；敏感路径改动而证据不足时必须 `BLOCK`。

## 按敏感面检查

| 敏感面 | 最低可验证证据 |
| --- | --- |
| 接口、认证 | 未登录请求得到 401/403；失效 Token 不可继续使用。 |
| 鉴权、权限、数据 | 普通用户不可访问管理员资源；用户 A 不可读取或修改用户 B 数据；租户归属来自服务端认证上下文。 |
| 支付、后台管理、用户数据 | 权限拒绝、资源归属和关键状态变更的测试或请求/响应；证据不足时 `BLOCK`。 |
| 文件 | 非法类型、路径遍历被拒绝；上传/下载有认证与归属校验。 |
| 输入处理 | 参数化查询或等效安全 API 的 diff 证据；危险输入被拒绝；回调签名/来源已校验。 |
| 敏感信息、日志 | 密钥扫描通过；日志和错误响应不含敏感值；疑似泄露按 P0。 |
| 配置、部署 | 配置 diff 和相关配置/镜像/IaC 扫描结果。 |
| 依赖 | 漏洞扫描结果；可利用风险为 P1，影响核心数据时升级 P0。 |
| CI | 工作流 diff、权限、扫描实际结果；不得跳过或泄露 Secret。 |

## 外部 API、批处理与日志

外部 API 或批处理改动应覆盖边界批次、部分失败、全部失败和调用方状态映射。API/网络失败不得展示为“未找到”或“未匹配”。

若失败详情只写入 `logger.extra`，需要提供 formatter、日志样例或日志平台查询证据；没有证据时列为 P2，并建议输出不含手机号、Token、Cookie 等敏感值的安全诊断信息。
