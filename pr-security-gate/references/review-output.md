# PR Code Review 固定输出模板

仅用以下结构输出。未知元数据、测试、扫描或请求/响应写“未提供”；没有问题时仍保留对应标题。

```markdown
Code Review 完成
仓库：<owner/repository>
分支：<分支名>
提交：<SHA 或提交范围>
提交信息：<提交信息>
提交者：<提交者>
Review 模式：incremental / full / 其他

判定结果：BLOCK / PASS
合并动作：禁止合并 / 可合并
结论依据：<最高风险或可合并的可观察依据>

审查范围：
- 本次范围：<提交数、文件或实际审查范围>
- 未审查范围：<未提供 diff、未运行检查等；无则“无”>

审查摘要：<1–3 句概述实际改动、关键风险和结论>

值得肯定：
- <有证据支持的正确设计、修复或测试；无则“无”>

变更的敏感面：
- 接口：涉及 / 未涉及 / 无法判断；<理由>
- 认证：涉及 / 未涉及 / 无法判断；<理由>
- 鉴权：涉及 / 未涉及 / 无法判断；<理由>
- 权限：涉及 / 未涉及 / 无法判断；<理由>
- 数据：涉及 / 未涉及 / 无法判断；<理由>
- 文件：涉及 / 未涉及 / 无法判断；<理由>
- 配置：涉及 / 未涉及 / 无法判断；<理由>
- 依赖：涉及 / 未涉及 / 无法判断；<理由>
- CI：涉及 / 未涉及 / 无法判断；<理由>

已验证证据：
- Diff 审查：<文件、位置和实际控制；未提供则“未提供”>
- 测试：<测试名、命令、结果；未提供则“未提供”>
- 扫描：<密钥、静态、依赖、镜像/IaC 扫描的实际状态；未提供则“未提供”>
- 关键请求/响应：<身份、方法、路径、状态码和边界；未提供则“未提供”>
- 日志可观测性：<formatter 或日志平台证据；未提供则“未提供”>
- 未验证声明：<作者或他人的声明；无则“无”>

需关注的问题：
- [P0] [HIGH] / [P1] [MEDIUM] / [P2] [LOW] <标题>
  - 位置：<文件:行号或范围>
  - 类型：安全 / 正确性 / 可用性 / 数据完整性 / 可观测性 / 可维护性
  - 依据或变更前后行为：<diff 或证据>
  - 攻击路径或失败路径：<如何触发>
  - 影响范围：<账户、租户、数据、系统、审计或业务范围>
  - 修复建议：<可执行修复与需补充验证>
  - 是否阻塞合并：是 / 否
  - 状态：未解决 / 已缓解
- 无：<没有问题时填写；否则不得填写“无”>

技术债：<N> 项
```

## 结论校验

| 判定结果 | 必须满足 | 不得发生 |
| --- | --- | --- |
| `BLOCK` | P0、涉及的敏感面缺少对应证据、缺失实际 PR diff，或人工安全复核尚未完成 | 标记为可合并，或将 P0 作为技术债延期。必须指明缺失证据对应的敏感面；不得把 CI/配置证据不足写成接口鉴权证据不足。 |
| `PASS` | 没有 P0，也不存在涉及的敏感面证据不足；P1/P2 已在“需关注的问题”列出，并计入技术债数量 | 因 P1/P2 缺少 Issue、负责人或截止日期改为阻断；将未提供扫描写成通过。 |

`CONDITIONAL` 不作为本版本报告的判定结果。技术债只记录 P1/P2 的数量，不重复展开问题详情。
