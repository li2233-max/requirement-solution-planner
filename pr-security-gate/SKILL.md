# PR 安全审查门禁

## 核心原则

基于实际 PR diff 和可复验证据输出可追溯的 Code Review 报告。AI 推断、作者声明和未运行的检查不是证据。P0 或敏感路径无法证明安全时必须 `BLOCK`；只有 P1/P2 时可 `PASS`，技术债只记录数量，不阻止合并。

## 输入与审查流程

- 使用实际 PR diff；没有 diff 时不得 `PASS`。
- 记录仓库、分支、提交、提交信息、提交者和 Review 模式；未知项写“未提供”。
- 标记接口、认证、鉴权、权限、数据、文件、配置、依赖和 CI 是否涉及；每项只能为“涉及”“未涉及”或“无法判断”。
- 只列出可复现证据：diff、测试名与结果、扫描输出、关键请求/响应和可见的服务端控制。
- 检查认证、授权、资源归属、输入处理、敏感信息、数据暴露、文件、依赖、部署配置、错误语义和可观测性。
- 对 `raise` 改为 `{}`、`[]`、`None`、`False` 等降级返回，检查调用方是否把 API 失败误标为“未找到/未匹配”；检查部分或全部批次失败是否可见。
- 详细证据规则见 [references/evidence-requirements.md](references/evidence-requirements.md)，报告必须遵守 [references/review-output.md](references/review-output.md)。

## 风险与合并规则

| 等级 | 典型情况 | 结论与合并动作 |
| --- | --- | --- |
| P0（报告标记 `HIGH`） | 密钥、Token、私钥或 `.env` 泄露；未登录私有访问；跨用户/租户越权；管理员接口缺少服务端校验；SQL/命令注入、RCE；敏感数据日志；敏感路径无法证明安全 | `BLOCK`，禁止合并和上线；泄露凭据必须移除、检查历史并吊销/轮换。 |
| P1（报告标记 `MEDIUM`） | 中等安全、正确性、数据完整性或可观测性问题，例如外部 API 失败被映射为“未匹配”、不安全配置、可能可利用的依赖漏洞 | `PASS`，可合并；计入技术债数量。 |
| P2（报告标记 `LOW`） | 低影响安全可维护性、非关键安全头、低影响依赖告警或日志诊断不足 | `PASS`，可合并；计入技术债数量。 |

`CONDITIONAL` 仅保留为历史兼容枚举；不得因 P1/P2 输出它。工程问题若影响权限结果、核心数据完整性、资金、工资、考勤结算或审计可见性，按实际影响升级为 P0 并 `BLOCK`。

## CI 与人工复核

- `BLOCK` 必须映射为失败的 `pr-security-gate` 检查。
- `PASS` 可包含 P1/P2；技术债详情放在“需关注的问题”，技术债区只输出数量。
- 涉及登录、权限、支付、用户数据、后台管理、文件上传或外部回调而授权证据不足时，保持 `BLOCK` 并要求人工安全复核。
- 不得把未提供的测试、扫描或请求/响应写成“通过”。
